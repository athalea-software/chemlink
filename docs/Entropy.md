# Binding energy with entropy

The dynamics analysis can turn on an entropy estimate in gmx_MMPBSA:

- `--mmpbsa-entropy none`: explicitly turns off the entropy correction.
- `--mmpbsa-entropy ie`: interaction entropy (IE); the default.
- `--mmpbsa-entropy c2`: C2 approximation.

The temperature of the entropy calculation is the dynamics temperature (300 K) and the IE
segment is 25% of the trajectory; both are fixed because the dynamics generated by ChemLink
always run at 300 K.

`--mmpbsa-entropy` is accepted by the types with a binding energy (`pligand`, `ppeptide`,
`pprotein`, `ppligand`), by `dynamic analyze` and by `hpc dynamics`. Re-analysis turns IE on by default even if an earlier run saved `none`. To turn entropy off, pass `--mmpbsa-entropy none`; to use C2, pass `--mmpbsa-entropy c2`. The other options keep the saved configuration when no new values are given.

The full `pligand` workflow runs the binding analysis with IE once the dynamics finish, without adding an entropy option:

```bash
chemlink dynamic pligand          # protein and ligand detected in the current directory
```

To run that workflow without the entropy correction:

```bash
chemlink dynamic pligand --mmpbsa-entropy none
```

To re-analyze an existing simulation without repeating the dynamics:

```bash
chemlink dynamic analyze --only binding    # latest run in results/dynamics
chemlink dynamic analyze /path/to/simulation --only binding
```

To use C2, add `--mmpbsa-entropy c2`; to turn entropy off, add `--mmpbsa-entropy none`. `--mmpbsa-frames` and `--mmpbsa-discard` control the set of frames used for energy and entropy. An entropy estimate requires checking its stability as the sampling changes; increasing the number of frames does not guarantee convergence.

## Results

The corrected estimate is `ΔG_bind ≈ ΔE_MM + ΔG_solv − TΔS`. The IE and C2 methods are approximations, not calculations of the full binding entropy.

In `binding_energy_analysis/gmx_MMPBSA/`:

- `SUMMARY_REPORT.txt` shows the base energy, the `−TΔS` correction, the estimated free energy, the temperature and any available diagnostics.
- `binding_energy.png` compares the base and corrected energy when the correction exists.
- `analysis_metadata.json` keeps `total_mean`/`total_std` as the base energy and adds `corrected_mean`, `corrected_uncertainty` and `entropy_correction`. The latter is computed as the difference between the two totals rounded by gmx_MMPBSA; `entropy_reported_correction` also keeps the contribution from its entropy table when available.
- `FINAL_RESULTS_MMPBSA.dat` keeps the original results and their uncertainty tables.
- The time series and its plot show energy **without** entropy: the correction is estimated over a set of frames, not for each individual frame.

The base uncertainty is the standard deviation over frames. The corrected uncertainty is copied from gmx_MMPBSA; its definition depends on the version. It should not automatically be read as the same standard deviation or as a confidence interval.

The gmx_MMPBSA version, the standard deviation of the interaction energy (`σ`) and the warnings/diagnostics produced by the engine are recorded. In 1.6.x versions, `ie_segment` sets the final stretch used in the IE summary. In recent development versions, it controls a convergence diagnostic and the main result uses the full set. ChemLink keeps the engine's result without changing its definition. See the [gmx_MMPBSA documentation](https://valdes-tresanco-ms.github.io/gmx_MMPBSA/dev/input_file/) for the version in use.

If the engine fails when entropy is turned on, ChemLink keeps the logs and input of that attempt with the `entropy_attempt_` prefix and makes a second attempt with entropy turned off. This may repeat the base energy calculation. If it recovers the base energy, it marks the analysis with warnings and the correction as incomplete. If the recovery also fails, it marks the analysis as failed.
